# AbioticSplitScreen — экспериментальный прототип

Цель: Abiotic Factor, Steam, один ПК с Windows, один процесс игры, два DualSense,
две независимые камеры и персонажа. Начальное разделение — сверху/снизу.

**Статус: прототип для проверки возможности, а не готовый мод для прохождения.**
В облаке нет установленной игры, Windows и геймпадов. Пользовательские журналы для
игры 1.5.0.31459 (UE 5.4.4) и UE4SS SHA 1ba38db4 подтверждают создание двух локальных
контроллеров и двух разных персонажей. После ручного переноса F5 пользователь
подтвердил исчезновение чёрного изображения; скриншот показывает два разных вида
мира и персонажей, видимых друг другу. Это подтверждает результат данного теста,
а не исправление всех возможных причин чёрного экрана. После v0.5 скриншот показывает
основной HUD в обеих половинах. Пользователь подтвердил проверку выбора ячеек 3/4
и открытия инвентаря клавишей Tab. Это не подтверждает независимые сохранения или
полную корректность данных здоровья/перков. По уточнению пользователя геймпады сейчас
отсутствуют; их тесты отложены. Новые требования: полноэкранное общее Esc-меню,
переключение клавиатуры/мыши между игроками, создание второго персонажа с перками
и отдельным сохраняемым прогрессом. Эти требования остаются активными.
Тесты с имитацией Unreal проверяют только поведение Lua-кода.

Прислать свежий `ue4ss/UE4SS.log`. Не нужно забирать предметы. Ниже сохранена история

к этой диагностической сборке. Tab/Esc используют проверенное закрытие своего окна.

В последнем запуске v0.8.4 пользователь подтвердил: предмет снова получил первый.
LOOTBIND показал два уже гостевых адресата: InventoryModeRefreshed и OnClicked

`script_probe.lua` по F6 читает код Blueprint выбранных функций контейнера,
корневого инвентаря и его сетки. Используется расширенный официальный
[RegisterCustomProperty](https://github.com/UE4SS-RE/RE-UE4SS/blob/1ba38db4/docs/lua-api/global-functions/registercustomproperty.md):
алиас byte TArray для UFunction.Script. Регистрация создаёт описание поля в UE4SS;
сам массив скрипта не меняется. Условия допуска: SHA UE4SS 1ba38db4, UE 5.4,
одинаковое смещение Script=0x60 в заголовке текущего журнала, размеры ArrayProperty=16
и ByteProperty=1 и пустой Script у нативной GetPlayerController. Размеры подтверждены
последним журналом и точным исходником LuaMod.cpp. Любое расхождение останавливает сбор.
Это обращение к нативным данным: совместимость чтения в самой игре ещё не проверена.

Перед чтением проверяются владелец нижнего инвентаря и контейнера, отдельные Pawn,
Pawn.InventoryReference и ActorComponent активного контейнера. Проверяются адрес
поля массива, Num/Max, положительный адрес данных, лимит 128 КБ на функцию и
256 КБ на отчёт. Читаются только индексы 1..Num, длина проверяется перед каждым
доступом и после него, последний байт должен быть EndOfScript. Пустые массивы не
индексируются. В UE4SS этого SHA getter за пределами массива способен его увеличить,
а ForEach имеет комментарий о повреждении Lua stack: оба пути исключены.
Все обращения выполняются в игровом потоке; pcall не перехватывает нативный access violation.

Каталог ограничен тремя уровнями известных классов, 384 функциями на класс,
2048 описаниями полей и 128 кандидатами для экспорта. Нет вызова экспортируемых
обработчиков, поиска всех UObject, изменения делегатов, байткода, предметов, ID,
перков или сохранений. Native hooks v0.8 остаются выключенными. При F1/F2/E новый
сборщик не регистрирует свойство и не читает Script. F6 заменяет прежний общий скан.
Один успешный отчёт за запуск, строки SCRIPTTRACE содержат последовательные блоки
hex и Adler32. Пользовательские дампы не включать в публичный репозиторий.

`python tools/read_script_report.py /path/to/UE4SS.log` проверяет полноту, границы,
порядок и контрольные суммы. Затем перечисляет статические совпадения указателей
в CallMath/FinalFunction/LocalFinalFunction с каталогом символов, отмечая простые
Self / integer-zero аргументы известных player-getter. Это не полный дизассемблер,
не подтверждение границ инструкций или исполнения ветки. Исправление следует
разрабатывать по фактическому коду и сигнатурам, не угадывая вызовы переноса.

В облаке прошли 229 Lua-проверок и 7 проверок Python-парсера; 101 Lua-проверка
относится к отключённым экспериментам. Они не подтверждают работоспособность
этих функций в игре. Общая пауза, независимая метка и предпросмотр, анимации,
создание гостя с собственными перками и сохранение его прогресса остаются открытыми.

у известных окон нижнего инвентаря, контейнера, его сетки, кнопки и трёх Keybind_TakeAll.
Только объекты с подтверждённым владельцем-гостем допускаются в эту область;
для native Button проверяется цепочка Outer до принадлежащего гостю UserWidget.
Нет поиска всех виджетов или перехвата выполнения функций.

Если подписчик точно равен известному экземпляру верхнего HUD/инвентаря/его
соответствующего дочернего окна либо первому контроллеру/Pawn, принимается только
соответствующий объект второго с **тем же классом**. Имя функции берётся из
существующей подписки, её наличие проверяется в классе адресата; RPC и сигнатуры
делегатов не перенаправляются. Неизвестные адресаты сохраняются. Отсутствие
предполагаемой связи не ведёт к угадыванию имени или созданию обработчика.

Multicast меняется точечными Remove/Add с проверкой всего состава подписчиков;
остальные слушатели сохраняются, уже имеющийся guest callback не дублируется.
Single-cast получает тот же FName с новым Object. Частичный сбой откатывается по
известным промежуточным состояниям. При F8 исходный список возвращается только
если текущий список всё ещё соответствует изменению мода; внешнее добавление,
замена или очистка событий сохраняются. Относительный порядок нового подписчика
после Add может отличаться, нативное поведение требует проверки.

Скан ограничен известными объектами, тремя классами на объект, 32 свойствами
делегатов на объект, 64 подписчиками на событие и 128 планами изменения. Дубликаты,
недействительные адресаты и недоступный API пропускаются с объяснением.
LOOTBIND сообщает фактический event, роль и существующее имя callback, затем число
изменённых событий. Broadcast/Clear, новые Lua callback, обработчик F, перенос
предметов, save-вызовы, изменение флагов UFunction и глобальные hooks не добавлены.
Проверенное закрытие inventory_ui.lua остаётся без изменений.

Это проверка конкретной связи событий, **а не подтверждённая причина/починка F**.
Если обработчик уже связан с гостем, но внутри сам выбирает player0, перенаправление
подписчика не решит эту отдельную проблему; для следующего шага нужен фактический
LOOTBIND пользователя. Тесты используют mocked delegates, не запущенную игру.

после искусственной ошибки копирования прошли. Это не запуск Windows-игры.

UE4SS, полностью перезапустите игру. Не используйте hot reload для этого прототипа.

## Установка на ПК

1. Установите совместимую с вашей версией игры сборку **UE4SS for Abiotic Factor**
   по инструкции её автора: <https://github.com/igromanru/AF-UE4SS>.
   Не предполагается, что любой последний релиз UE4SS подходит любой версии игры.
   Сначала проверьте, что игра запускается с одним UE4SS без этого прототипа.
2. В Steam откройте свойства Abiotic Factor → «Контроллер» и включите Steam Input
   для двух DualSense. Проверьте, что Steam видит оба устройства отдельно.
   Для первого испытания не запускайте параллельно другой эмулятор контроллеров.
   Если без мода один DualSense не управляет игрой, сначала устраните эту проблему.
3. В Steam выберите «Управление» → «Просмотреть локальные файлы».
   Найдите установленную папку `ue4ss/Mods` рядом с игровым Win64-бинарником.
   Типичный относительный путь: `AbioticFactor/Binaries/Win64/ue4ss/Mods`.
   Положение зависит от сборки загрузчика; используйте его фактическую папку Mods.
4. Распакуйте архив так, чтобы получились:

   ```text
   ue4ss/Mods/AbioticSplitScreen/enabled.txt
   ue4ss/Mods/AbioticSplitScreen/Scripts/main.lua
   ue4ss/Mods/AbioticSplitScreen/Scripts/split_probe.lua
   ue4ss/Mods/AbioticSplitScreen/Scripts/session_tools.lua
   ue4ss/Mods/AbioticSplitScreen/Scripts/player_bindings.lua
   ue4ss/Mods/AbioticSplitScreen/Scripts/hud_link.lua
   ue4ss/Mods/AbioticSplitScreen/Scripts/routing_probe.lua
   ue4ss/Mods/AbioticSplitScreen/Scripts/inventory_ui.lua
   ue4ss/Mods/AbioticSplitScreen/Scripts/container_handoff.lua
   ue4ss/Mods/AbioticSplitScreen/Scripts/container_actions.lua
   ue4ss/Mods/AbioticSplitScreen/Scripts/container_delegates.lua
   ue4ss/Mods/AbioticSplitScreen/Scripts/script_probe.lua
   ue4ss/Mods/AbioticSplitScreen/Scripts/waypoint_ui.lua
   ```

   Либо скопируйте папку `mods/AbioticSplitScreen` из репозитория в `ue4ss/Mods`.
   Не заменяйте существующие чужие моды или `mods.txt`.
5. Запустите игру. В журнале UE4SS должна появиться строка
   `[AbioticSplitScreen] Experimental probe v0.8.5 read-only handler diagnostic loaded` и сообщение об отключённом
   эксперименте v0.7. После F1 ожидаются `HUDLINK guest PlayerHUDRef and OwningCharacter verified`
   и `INVLINK guest Pawn.InventoryReference matches its own inventory widget`.

## Первое испытание раннего прототипа (история, до v0.8.5)

1. Создайте отдельный тестовый мир, загрузитесь LAN-хостом с лимитом минимум 2 игрока
   и пустым паролем; дождитесь управления персонажем.
2. Нажмите F6. Ожидается один локальный слот с контроллером и персонажем.
3. Нажмите F7 **один раз**, подождите несколько секунд и снова нажмите F6.
4. Зафиксируйте: стало ли два слота; есть ли персонаж у каждого; появились ли два
   изображения; управляет ли каждый DualSense только своим персонажем.
5. Нажмите F8. Ожидается возврат к одному локальному слоту и исходным настройкам.

Для обновления с первой версии при закрытой игре достаточно заменить только
`Scripts/main.lua`; `split_probe.lua` остаётся тем же. Сохраните старый файл отдельно.
После полного перезапуска и однократного F7 можно нажать F9 один раз и F6 для записи
состояния камеры. Подождите несколько секунд и сообщите, изменилось ли нижнее изображение.
Оба DualSense проверяются отдельно: движение и поворот каждым геймпадом по очереди.

v0.3 можно установить поверх v0.2, добавив в конец `main.lua` только блок после
комментария `v0.3: opt-in spawn experiment`. Полный main.lua уже включает его —
не добавляйте блок дважды. В журнале должен появиться маркер `v0.3 add-on loaded`.

v0.4 добавляется поверх v0.3 блоком после комментария `v0.4: read-only HUD inspection`.
После полного перезапуска игры и повторения успешной последовательности F7, F5
нажмите F6. Для следующего этапа нужен UE4SS.log со строками `HUD root` и `HUD scan`.
Не переподключайте неизвестные виджеты и не создавайте новый HUD до установления
того, какие корневые виджеты созданы игрой для каждого игрока.

Пользовательский журнал v0.4 установил: единственный основной `W_PlayerHUD_Main_C`
принадлежит Player 0. В viewport также находятся `W_UIPopupOverlay_C`,
`W_PlayerHUD_RecipeVBox_C`, `W_BetaWatermark_C`, `W_PlayerHUD_InteractionPrompt_C`;
все принадлежат Player 0. Отдельного основного HUD Player 1 этот скан не нашёл.

v0.5 можно добавить к v0.4 блоком после комментария `v0.5: opt-in HUD layout experiment`.
В отдельном тестовом LAN-мире выполните успешную последовательность F7, F5, дождитесь
обновления изображения и нажмите F4 один раз, затем F6. Ожидаемый проверяемый результат —
основной HUD в каждой половине. Если появились пустые/неверные шкалы или проблемы меню,
нажмите F3 и приложите UE4SS.log. Для проверки независимых данных потребуется отдельно
сравнить владельцев, изменения здоровья и содержимое инвентарей: одинаковое оформление
двух HUD не доказывает, что они читают данные разных персонажей.

В пользовательском журнале v0.2 F9 отработала, view target второго игрока был его
собственным персонажем, а после обновления камера следовала за ним. Однако Z первого
персонажа был около 208 см, второго — 21608 см. Это подтверждает разницу высоты около
214 м, но не доказывает причину чёрного изображения. F5 проверяет гипотезу о месте
появления персонажа. Числовое значение FadeAmount не удалось прочитать: UE4SS вывел
`TrivialObject`, поэтому наличие/отсутствие затемнения по этой строке не установлено.

## Диагностированные ограничения входа

Журналы пользователя подтвердили две разные причины отказа `CreatePlayer`:

- `ServerFull` при первом запуске. Следующий запуск LAN-хостом с `MaxPlayers=2`
  устранил этот отказ.
- `Join_PasswordInvalid` после включения хостинга. Создание второго игрока удалось
  в следующем тесте после рекомендации запустить тестовую LAN-сессию без пароля.
  Сам `CreatePlayer` в этом прототипе не передаёт параметры пароля; поддержку
  защищённых сессий ещё предстоит реализовать.

После любого отказа не нажимайте F7 повторно: текущая версия блокирует новую попытку
до полного перезапуска игры, поскольку вызов движка мог завершиться частично.

Для следующей итерации нужны версия игры, версия сборки UE4SS и строки журнала
с префиксом `[AbioticSplitScreen]`, включая ошибку/стек при сбое. Перед передачей
журнала уберите личные пути и идентификаторы. При сбое запуска удалите папку
`AbioticSplitScreen` при закрытой игре.

## Что предстоит реализовать после проверки

Пользовательский тест v0.6 подтвердил переключение движения и камеры на гостя,
но Tab/Esc у гостя не открывались, а при подборе ресурса анимация проигрывалась
у первого персонажа. Следовательно, проверка верхнего HUD 3/4/Tab не подтвердила
полную независимость второго игрока. В тесте v0.7 Tab остался неработоспособным;
ошибки интерфейса, маршрутизации анимаций и самостоятельной работы гостя остаются открытыми.

Журнал v0.6 установил точный Esc-виджет W_EscapeMenu_Main и флаг GameMode.bPauseable=true.
В момент снимка Esc мира IsGamePaused=false. Полноэкранное меню и нативный запрос
паузы реализованы как проверяемый эксперимент v0.7, но работа в игре ещё не подтверждена.

Создание гостя с перками и независимым сохранением пока не реализовано. Проверены
публичные объявления UAbioticGameInstance: GetPlayerSave(PlayerId, bCreateIfNotFound),
DoesPlayerSaveExist, AddPlayerSaveToQueue, PlayerSaveClass/MetaDataSaveClass и
UAbioticSave.SaveIdentifier. Эти методы в новой диагностике не вызываются. Нужны
фактические Blueprint-поля и пути загрузки/применения данных текущей версии игры.
Дополнительные метаданные текущей игры: Blueprint PlayerState имеет UniquePlayerID,
PlayerSaveID, CurrentPlayerSaveData, HasLoadedSave и методы SavePlayerData,
LoadPlayerSaveData, Apply Save Data to Character. Native PlayerSaveClass —
AbioticCharacterSave с CharacterSaveData. На контроллере есть GoToTraitsSelection,
Client_DoTraitSelectionSequence, Server_SetupInitialTraits, HasCompletedTraitSelect
и ClientHasRecievedCharacter. Значения ключей и сигнатуры этих вызовов ещё не
подтверждены полностью; последний журнал установил совпадение обоих ID и незавершённые
флаги инициализации гостя. Значения ID не печатаются. Простая смена имени или
PlayerState.PlayerId не создаёт отдельный профиль прогресса.
До установления отдельного save identifier не записывайте новую гостевую информацию
в сохранение хоста и не выдавайте JSON с настройками за сохранение персонажа игры.

- Если локальный слот не создаётся — разобраться с игровыми ограничениями входа/создания игрока.
- Если слоты есть, но экран один — исследовать viewport и возможное принудительное отключение split-screen.
  Изменение CDO настроек само по себе не гарантирует перерисовку или отключение игрового override.
- Если нет второго персонажа — исследовать создание персонажа и вход гостя в игровой режим.
- Проверить назначение устройств каждому LocalPlayer и Enhanced Input; настройка Steam Input
  сама по себе не реализует разделение ввода внутри игры.
- Разделить HUD, инвентарь, взаимодействия, меню и паузу по владельцам игроков.
- Проверить уникальность личности гостя и независимость сохранений, возрождение,
  перемещение между секторами, загрузку мира и повторный вход.

Игра может предполагать одного локального пользователя Steam. Даже успешный
`CreatePlayer` не доказывает корректную загрузку/сохранение второго персонажа.
Если Lua и отражённых функций окажется недостаточно, следующий этап — нативный
мод UE4SS на C++ с данными именно вашей сборки, а не неподтверждёнными смещениями.

## Проверки разработчика в облаке

```bash
cd /workspace/AbioticMod
/workspace/.abiotic-tools/venv/bin/python tools/check.py
/workspace/.abiotic-tools/venv/bin/python tools/package.py --output /tmp/AbioticSplitScreen-prototype.zip
```

Среда тестов: Python 3.12, `lupa==2.6`, Lua 5.4. Windows-пакет собирается из Lua-файлов;
Unreal Editor и компиляция UE4SS для этой итерации не нужны.
